# Acquisition and IP Handover Notes

## Repository role

**Product or component repository**

This file is an operational handover aid. It does not establish legal ownership, assignment, inventorship, trademark rights, or third-party license compliance.

## Canonical status

- Canonical status: **Supporting surface; cranium-kernel is canonical**.
- Default branch: \">main\".
- Repository owner at preparation time: \">worthwyl2022-cloud\".
- Historical, experimental, generated, and demonstration material must be labeled before transfer.

## Reproduction checklist

1. Clone the repository and check out the default branch.
2. Record the runtime, package-manager, dependency, and tool versions used for validation.
3. Follow the repository README and record the exact build, test, and demo commands.
4. Record expected outputs, known failures, external services, and required environment variables.
5. Do not place credentials, private keys, customer data, or confidential contracts in this repository.

## IP and provenance checklist

- [ ] Identify the original author and contributors from repository history.
- [ ] Inventory third-party code, dependencies, generated assets, fonts, media, models, and external services.
- [ ] Confirm the intended license or proprietary treatment for each material category.
- [ ] Identify items requiring separate assignment, consent, or exclusion.
- [ ] Preserve historical provenance when material is moved or consolidated.
- [ ] Link the repository to the portfolio-level canonical architecture map.

## Security checklist

- [ ] Run secret scanning against the working tree and relevant history.
- [ ] Review issues, pull requests, releases, actions, deploy keys, and environment configuration.
- [ ] Rotate any credential that may have appeared in history; deleting a file is not sufficient.
- [ ] Document externally managed domains, cloud resources, registries, and service accounts separately.

## Transfer acceptance criteria

A transferee should be able to identify the repository's purpose, reproduce the documented behavior, understand its architecture and limitations, and distinguish owned material from third-party or unverified material. Legal clearance remains a separate diligence workstream.
